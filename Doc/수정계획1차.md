# 수정 계획 1차

## 문서 목적

현재 `StoryManager` 기반 Phase 경로 프리뷰 기능에서 확인된 시각화 문제를 정리하고, 각 문제에 대해 **원인 요약**, **수정이 필요한 지점**, **수정 후 확인 항목**을 기록한다.

이번 문서는 구현 완료 보고가 아니라, **1차 수정 착수 전 정리 문서**에 해당한다.

## 이슈 1. Manager 근처의 불필요한 선 표시

원인 요약: `USplineComponent` 생성 직후 기본 스플라인 포인트가 남아 있는 상태에서 NavPath 점을 추가해, 의도하지 않은 기본 구간이 `Manager -> Ally` 선처럼 표시된다.

수정 필요 부분

1. 프리뷰 스플라인 생성 직후 기본 포인트를 비우는 초기화 단계를 먼저 수행하도록 정리한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - `AStoryManager::RebuildPhasePreview()`
   - `USplineComponent* PreviewSpline = NewObject<USplineComponent>(...)` 직후 구간
   - `PreviewSpline->AddSplinePoint(...)` 호출 전에 기본 spline point 제거 또는 point 배열 초기화 코드 삽입

2. 경로 점 입력 방식을 현재의 누적 추가형에서 전체 세팅형으로 바꿀지 검토하고, 필요하면 그 방향으로 정리한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - `for (const FVector& PathPoint : NavigationPath->PathPoints)` 루프
   - 현재 `AddSplinePoint()` 중심 작성부
   - 필요 시 `SetSplinePoints()` 또는 동등한 전체 point 세팅 방식으로 교체

3. 실제 프리뷰에 남아야 하는 시각화 구간을 `Ally -> TargetPoint`만 남도록 기준을 고정한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - NavPath 점에 `PreviewPathZOffset`을 더해 spline에 넣는 구간
   - spline point 타입을 `Linear`로 지정하는 구간
   - 시작점이 spline 기본점이 아니라 첫 NavPath 점인지 보장하는 로직

사용자 확인 체크리스트

- `Phase1` 선택 상태에서 `Manager` 근처의 불필요한 선이 남지 않는지
- `Phase2` 선택 상태에서도 동일한 형태로 깨끗하게 보이는지
- Ally가 여러 명일 때 각 선의 시작점이 `Manager`가 아니라 각 Ally 위치인지
- TargetPoint가 바뀌어도 시작점이 spline 기본점이나 `Manager` 쪽으로 되돌아가지 않는지

## 이슈 2. StoryManager 재선택 시 프리뷰 미복구

원인 요약: 현재 프리뷰 갱신이 selection change 자체를 직접 처리하지 않고 `Tick`, `Construction`, `PropertyChange` 흐름에 의존해, 아웃라이너 재선택 시 프리뷰 재생성이 안정적으로 보장되지 않는다.

수정 필요 부분

1. 선택 상태 감지 흐름을 재검토하고, 선택 해제와 재선택을 각각 어떤 조건에서 처리할지 분리해 정리한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - `AStoryManager::HandleEditorPreviewTick()`
   - `const bool bShouldShowPreview = bShowPhasePreview && IsSelectedInEditor();`
   - `bPreviewVisibleInEditor`, `bPreviewDirty` 상태값을 어떻게 갱신할지 재정의

2. 프리뷰 제거 시점과 재생성 시점을 분리해서, 재선택 직후 다시 그려질 수 있는 흐름으로 정리한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - `ClearPhasePreview()`
   - `RebuildPhasePreview()`
   - 선택 해제 시 제거, 재선택 시 재생성으로 이어지는 분기 순서

3. 현재의 폴링 기반 방식만으로 충분한지 판단하고, 필요하면 selection change 대응 구조를 더 직접적으로 도입한다.
   세부 편집 대상
   - `Source/COD/Private/StoryManager.cpp`
   - `Tick()`, `OnConstruction()`, `PostEditChangeProperty()`에서 `HandleEditorPreviewTick()`를 호출하는 구조
   - 필요 시 선택 변경 시점에 별도 재생성 트리거를 거는 방향 검토

사용자 확인 체크리스트

- 뷰포트에서 다른 액터 선택 후 다시 `StoryManager`를 선택했을 때 프리뷰가 바로 복구되는지
- 아웃라이너에서 `StoryManager`를 다시 선택했을 때도 같은 결과가 나오는지
- Details 패널에서 `PreviewPhase`를 바꾼 뒤 선택 상태가 유지될 때 프리뷰가 즉시 갱신되는지
- `ShowPhasePreview`를 껐다가 다시 켰을 때도 프리뷰 표시 상태가 정상 복구되는지

## 공통 반영 원칙

1. 이번 수정은 **프리뷰 표시 안정화**가 목적이며, 기존 `ChangePhase()` 기반 런타임 동작에는 영향을 주지 않아야 한다.
2. 프리뷰용 스플라인은 선택 해제 후 정상 제거되고, 재생성 시 중복으로 남지 않아야 한다.
3. 최종 확인은 `BP_StoryManager`를 실제 레벨에 배치한 상태에서 수행한다.
